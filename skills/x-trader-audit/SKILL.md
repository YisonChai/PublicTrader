# X 交易博主胜率报告

接受 `@handle`、裸账号或 X 主页链接。默认目标仓库为 `YisonChai/PublicTrader`，网站为 `https://yisonchai.github.io/PublicTrader/`。用户指定其他仓库、日期范围或只生成本地报告时，以用户要求为准。调用本 skill 的默认工作包含该账号报告的发布和 README 更新。

使用随附的 `report.py` 和 `report-template.html`。脚本负责校验、统计、生成网页和更新索引。采集、语义配对、证券识别和行情核实由执行 skill 的 agent 使用当前可用工具完成。不要把关键词命中直接变成交易。

## 输入与准备

1. 将账号规范化，确认主页上的账号、显示名及可访问状态。检查目标仓库的 `AGENTS.md`、远端、分支和工作区。复用合适的 checkout，避免碰到其他任务的修改。
2. 查看 `reports/<handle>/summary.json`、现有报告内嵌数据及 README。更新时保留已有已核实证据，按状态 ID 合并新帖子，重新检查重复持仓和退出链。
3. 新建独立工作目录，初始化输入。以下 `SKILL_DIR` 指本 SKILL.md 所在目录，`WORK_DIR`、`REPORT_DIR` 和 `REPO_DIR` 使用本次实际绝对路径。

```bash
python3 "$SKILL_DIR/report.py" init --account "@handle" --workdir "$WORK_DIR"
```

读取 [schema.md](schema.md) 后填写 `manifest.json`、`posts.json`、`trades.json`、`market-prices.json`。不要在技能、报告或仓库中保存登录凭据、浏览器 Cookie、付费 API 密钥或私有消息。

## 采集公开记录

- 优先使用已连接且支持该数据的 X 工具或用户提供的导出。其次使用已授权浏览器的公开 Posts、Replies、帖子详情和 X 搜索。需要登录时使用正常登录流程。付费服务只在已有使用授权和预算内调用。
- 默认尽可能覆盖可访问历史。按状态 ID 去重，只将目标作者的帖子和回复加入 `posts.json`。引用内容、转推、其他人的回复属于上下文，不能当成本人交易。
- 沿历史游标或页面向前采集，分批保存。若时间线截断，使用 `from:handle since:YYYY-MM-DD until:YYYY-MM-DD` 的日期窗口查询，覆盖成功记录范围以外的时期。补查 `filter:replies`。扫描所有取得的原文，按账号使用的语言识别进出场、加减仓、止盈止损和总结。
- 打开候选交易的完整详情、长文、连续回复和相关截图。图片中的价格须查看原图，OCR 后复核。关键词检索会遗漏委婉表达，不能仅靠固定中文或英文词表宣称穷尽。
- 记录每个查询窗口或游标的结果、去重数、最早/最晚时间、未展开帖和实际停止原因。同一游标重复或三次成功加载仍无新增时，转用日期窗口或记录该入口结束。限流按服务提示退避，重复技术失败则保留已得数据和缺口。被保护、已删除或无可访问记录时，明确说明，不能编出历史。
- `completeArchive` 默认 false。主页帖子总数与搜索结果数量的比例不等于覆盖率。`collectionStatus` 写实际 `partial` 或有充分依据的 `complete`，`collectedAt` 写真实采集时刻。

## 配对与行情

按时间核对同一证券、方向和持仓批次。一个持仓段包含加仓与减仓，不把每次喊单当一笔。区分已成交、操作计划、浮盈和事后回顾。相同平仓的重复复盘、组合合计和单项不重复计数。不能凭“反弹”“走了”或组合赚钱就判定某个单项盈利。

每笔保存入场、退出、结果依据的原文 ID 和配对解释。内部证据类型沿用 schema 中的 A/B/G/U，网页只显示中文。

- 主胜率只统计可配对且结果明确的公开样本，`赢 ÷（赢＋亏）`。持平单列，未平仓和结果未明不进分母。零分母显示“暂无可计算样本”。
- “已经止盈/止损”可用于自述结果，仍需查对应标的、对应日期的收盘价。计划止损价不能当实际退出价。原文价和行情估算冲突时保留双方及来源。
- 用公开市场资料核实证券身份、交易所、具体合约、报价币种和时区。泛称“纳指”“黄金”不能直接指定 ETF，期权收益不能套用正股价格。杠杆 ETF 按自身报价计算，不能再次乘杠杆。
- 查询入场与退出证据对应日的未复权收盘价，保存精确日期、来源 URL、币种和市场时区。美股通常使用 `America/New_York`，加密货币按所用数据源定义的日线。查明休市才填 `previousSessions`。行情缺行不能自动视为休市，盘中尚未完成的日线不能当最终收盘。
- 优先原文已披露价，缺少的一端用收盘补价。核对拆股、合股、代码变更、不同合约及币种后，才将 `proxyEligible` 设为 true。价格冲突、同日缺报价或不可比价格保留空值。源数据有错误或访问失败时记录原因，不换成猜测价格。
- 看清执行时间与发帖时间。若只有后来复盘而无法配对当时进出场证据，不能以复盘日行情冒充真实交易收益。任何参考百分比都不汇总成账户收益率。

完成逐笔复核后才把 `pairingReviewed` 设为 true。未披露的结果留 `未明`，模板按既定偏好隐藏这类列表项，但原始记录仍可检索。

## 生成与检查

```bash
python3 "$SKILL_DIR/report.py" build --workdir "$WORK_DIR" --output "$REPORT_DIR"
```

输出 `index.html`、`summary.json`、`manifest.json`、`trades.json` 和 `trades.csv`。网页内嵌原文与行情，支持离线搜索、证据弹窗和下载。

沿用黑色背景、中性灰毛玻璃卡片、84% 底色不透明度、20 px 卡片间距、大号收盘价日期、鲜明正负收益颜色。交易账本全量列出，不分页。筛选与说明使用中文，不显示 A/B/G/U 标记。

打开生成网页，确认账号、日期、统计和来源正确，验证搜索、证据详情、下载和窄屏布局。检查无盈利样本或空数据时无 NaN。抽查盈利、亏损、未平、缺报价及休市的实际证据和计算。脚本校验无法替代语义审核。

## 更新仓库并发布

README 使用 `<!-- trader-table:start -->` 和 `<!-- trader-table:end -->` 包住博主表格。首次接入其他仓库时，将原有博主行完整保留在标记内，列顺序为博主、平台、配对样本、样本胜率、报告。

```bash
python3 "$SKILL_DIR/report.py" stage --report "$REPORT_DIR" --repo "$REPO_DIR" \
  --site-url "https://yisonchai.github.io/PublicTrader"
```

只放置 `reports/<handle>/index.html`、`reports/<handle>/summary.json` 并更新 README 对应账号行。该命令不会改动其他账号报告，重复执行不会产生同账号重复行。现有根目录 `index.html` 是早期报告入口，新增账号使用独立目录。

检查 diff 后，提交本次账号的两个报告文件和 README，默认提交信息 `feat(report): audit @handle public trades`。按仓库规则使用已有获准分支或 `codex/audit-<handle>`，推送并完成用户授权的合并。遇到保护分支则保留 PR 并明确当前发布状态。

工具优先顺序为有写权限的 GitHub connector、已认证 Git CLI、已登录的 GitHub 网页。CLI 账号无写权限时，先核实其他已授权入口的身份和能力。网页上传须保留 `reports/<handle>/` 路径，不能把不同账号的 `index.html` 全部传到根目录。使用正常文件选择器，遵守当前浏览器工具说明。

GitHub Pages 使用仓库现有配置。等待本次 commit 的构建部署完成，若构建失败先诊断并修复本次改动。打开最终 `/reports/<handle>/` 网址，验证内嵌账号、样本统计和此次版本，确认后返回链接、样本数及关键覆盖限制。提交或部署失败时说明实际完成到哪一步，不声称已经上线。
